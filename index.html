1.1 Project Overview The Volume Link Discount Scheme (VLDS) Automation System is a standalone desktop application developed for Forest Dealerships to fully automate the quarterly incentive processing pipeline. The system replaces a manual, error-prone, three-to-five working day Excel-based process with an automated tool that delivers the complete incentive report in under fifteen minutes with zero manual calculation. The application is built using Python 3.10 with a Tkinter graphical user interface. It accepts multiple input Excel files, processes them through a nine-step business logic pipeline, and produces a professionally formatted three-sheet Microsoft Excel report with embedded live Excel formulas. A complete text-format audit log is generated with every run, recording every processing decision for traceability and dispute resolution. A key innovation of this system is the live Excel formula output. Rather than writing static calculated values, the application embeds Excel formulas for Increase, Growth Percentage, Discount Percentage (as a nested IF formula derived from the slab table), and Discount Value. This allows the Finance team to modify values such as previous year sales figures directly in the output Excel file and observe all dependent columns recalculate automatically without re-running the application. 1.2 Business Need and Problem Statement Prior to this system, the Finance team processed VLDS incentive data entirely by hand using Microsoft Excel. This manual process required two to three analysts working for three to five working days per quarter. The following systematic deficiencies were identified: Problem Root Cause Business Impact Severity Exclusion list applied inconsistently Subjective analyst interpretation of exclusion criteria Wrong dealers included in payout calculations Critical Previous year VLOOKUP failures Dealer code format differences between file years (12345 vs 12345.0) Growth percentage wrong for multiple dealers each quarter Critical Manual slab lookup errors Row-by-row incentive rate lookup for hundreds of dealers Incorrect incentive amounts calculated and disbursed Critical No audit trail No systematic recording of processing decisions Dealer disputes cannot be resolved; internal audit unsatisfied High No input file validation No verification that the correct file is loaded for each step Outdated or wrong files processed without detection High Processing takes 3–5 working days Entirely manual multi-step process Delayed disbursements and analyst overtime High Inconsistent report format Layout varies by analyst and quarter Management cannot make cross-quarter comparisons Medium No progress visibility Processing status unknown until completed Repeated status queries to team Low 1.3 Project Objectives Automate all nine steps of the VLDS incentive processing pipeline, eliminating all manual calculation, filtering, and lookup operations. Reduce quarterly processing time from three to five working days to under fifteen minutes. Deliver a fully dynamic system — all business rules (exclusion criteria, slab rates, dealer lists) are read from uploaded files at runtime with zero code changes required between quarters. Generate a standardised three-sheet Excel report with live Excel formulas enabling post-generation corrections without re-running the application. Provide a complete downloadable audit log for every processing run, including per-item exclusion audit with revenue impact, to support dealer dispute resolution and internal audit requirements. Deploy as a standalone Windows executable requiring no Python installation on client machines. Implement customer name deduplication by Customer Number to prevent duplicate rows in the incentive summary when dealers are renamed across quarters. 2. Every row is scanned. The first numeric value in each cell is extracted using Python regex (re.findall). Header rows containing text like 'Quarterly', 'Growth %', 'Incentive Payout' are silently skipped because their cells produce no numeric values. This formula is written into every cell of the Discount % column in the Final Summary sheet. For a four-bracket slab, the formula for row 4: =IF(H4<10.0, 0.5, IF(H4<20.0, 1.0, IF(H4<30.0, 1.5, 2.0))) H4 = Growth % cell in the same row. This occurs because the same Customer Number has different Customer Names across quarters — for example, one file has 'ABC Motors Pvt Ltd' while another has 'ABC Motors Pvt Ltd (formerly known as XYZ Dealers)'. The deduplication logic, applied in Step 7 before the pivot operation, works as follows: 1. Build a mapping: Customer Number → first Customer Name found 2. For each name, strip parenthetical text using regex: re.sub(r'\s*\(.*?\)\s*', '', name) 'ABC Motors (formerly known as XYZ)' → 'ABC Motors' 'DEF Auto (merged with GHI)' → 'DEF Auto' 3. Apply the cleaned name to ALL rows for that Customer Number 4. Log the count of deduplicated names as a warning Result: one pivot row per Customer Number, not per name variant 4. Logic and Business Rules Implemented 6.1 Dealer Code Normalisation Applied before every join/merge operation. The _norm_key() function converts all dealer codes to a consistent string format by stripping the .0 decimal suffix that appears when Excel exports integer codes as floats. For example, '12345.0' becomes '12345', and '67890.00' becomes '67890'. Codes already in clean format are left unchanged. This normalisation is applied to both sides of every matching operation. 6.2 4S Dealer Eligibility (Step 2) Only dealers present in the 4S Dealer List (Combined Reference File Sheet 1) are eligible for VLDS incentive. The matching is performed as an inner join on the normalised dealer code column. Dealers in the VLDS data not present in the 4S list are removed and counted in the audit log. 6.3 LOB Eligibility (Step 3) Only transactions in the PARTS and HIGHWAY Lines of Business are eligible. The LOB column is identified by keyword matching, and rows are filtered using a case-insensitive string comparison. All non-PARTS and non-HIGHWAY rows are removed. 6.4 Exclusion List Application (Step 4) This is the most complex filtering step and uses the four-column exclusion format described in Section 3.4. Each exclusion row specifies what to search for and where to search. The processing rules are: If Item Name is NA or N/A or blank: search the Particulars value in the column identified by 'Column where filter applied'. This handles cases like searching 'CSS EDO PARTS' in the Invoice Type column. If Item Name has a real value (e.g., 'A0753RG'): search the Item Name in the Item column of the VLDS data AND search the Particulars in the Line Item column. Either match flags the row. Flagged rows receive the remark 'Exclusion List - [Particulars value]' for traceability. Rows already flagged by a prior exclusion rule are not double-counted. A complete per-item audit is generated showing matched rules, unmatched rules, and revenue impact. 6.5 DF-RECD Matching (Step 5) The DF and RECD file identifies specific invoice records for exclusion. A composite BD key is constructed from multiple identifying columns in both the VLDS data and the DF-RECD file. Both sides of the key are normalised using _norm_key() before comparison. Records in the VLDS data whose BD key appears in the DF-RECD file are flagged with an appropriate remark. 6.6 Customer Name Deduplication (Step 7) Before the quarterly pivot is built, customer names are deduplicated by Customer Number. A regex pattern strips parenthetical text such as '(formerly known as XYZ Dealers)' from customer names. All rows for the same Customer Number are then assigned the cleaned version of the name. This prevents the same dealer from appearing as two separate rows in the pivot output, which would double their revenue figure and inflate the Grand Total. 6.7 Growth % and Incentive Calculation (Step 8) Calculation Formula Protection Written As Increase Final Amount Q-curr minus Final Amount Q-prev N/A Live Excel formula: =C4-D4 Growth % (Increase / Final Amount Q-prev) * 100 IF Q-prev = 0, Growth % = 0 (division-by-zero) Live Excel formula: =IF(D4=0,0,E4/D4*100) Discount % Slab bracket lookup on Growth % Last bracket catches all values above highest threshold Nested IF Excel formula from slab brackets Discount Value Final Amount Q-curr * Discount % / 100 N/A Live Excel formula: =C4*G4/100 Grand Total — Increase SUM of Q-curr range minus SUM of Q-prev range N/A Excel SUM formula Grand Total — Discount Value SUMPRODUCT(Q-curr range, Disc% range) / 100 N/A Excel SUMPRODUCT formula 7. Assumptions and Limitations 9.1 Assumptions The VLDS Main File contains at least one column identifiable as Revenue by keyword matching (revenue, sales, net, amount). Fallback: last numeric column is used. Dealer codes may appear in integer or float format across different files. The system normalises both sides before every matching operation. The Combined Reference File has at least three sheets. Sheets are mapped by keyword in their names or by position (1st = Dealer, 2nd = Exclusion, 3rd = Slab) if names contain no recognisable keywords. The Previous Year Summary file is the output from a prior VLDS processing run for the same quarter of the previous year. Slab payout values stored as decimal fractions (e.g., 0.02) represent percentages (2%). Auto-conversion is applied when all payout values are below 0.10. The Exclusion List Sheet 2 follows the four-column format: SR.NO, Particulars/Line Item, Item Name, Column where filter applied. Microsoft Excel 2016 or later is required on the client machine to open the output report and use the live formula functionality. The application is used by a single operator at a time. No concurrent multi-user processing is supported. Customer names containing parenthetical text like '(formerly known as ...)' represent the same entity as the name without the parenthetical text. 9.2 Limitations Limitation Detail Workaround Discount % static after generation Nested IF formula reflects slab at generation time. If slab is updated after report generation, old formula remains. Re-run the application with the updated slab file. Single-quarter processing No batch mode for multiple quarters or annual aggregation. Run four times (once per quarter); consolidate manually. 200 MB file size limit Very large files may exceed this limit. Split input files before processing. Windows 10/11 64-bit only macOS and Linux not supported in the .exe format. Run on a Windows machine. Prev year auto-detection Non-standard column names may cause wrong column selection. Verify auto-detected columns in UI before clicking Run. Exclusion text matching Uses case-insensitive substring matching — may match unintended items if exclusion text is too generic. Use specific, unique Particulars text in the exclusion list. Customer name dedup Regex strips ALL parenthetical text — may affect names where parentheses are part of the actual name. Verify deduplicated names in the pivot output. 10. User Interface Details 10.1 Main Window Layout The application window opens maximised on Windows. Deployment Approach and User Instructions 11.1 Building the Executable The application is packaged using PyInstaller from the development machine. The build bundles Python 3.10, all libraries, all modules, and the logo file into a single .exe of approximately 40–60 MB. Build Steps: 1. Open Command Prompt in the project folder 2. Delete old build: rmdir /s /q dist build 3. Run PyInstaller: pyinstaller --onefile --noconsole --name VLDS_Automation --add-data modules;modules --add-data logo.PNG;. --hidden-import pandas --hidden-import openpyxl --hidden-import xlsxwriter --hidden-import xlrd --paths . --paths modules app_tk.py 4. Output: dist/VLDS_Automation.exe 11.2 Client Machine Requirements Requirement Specification Operating System Windows 10 or Windows 11 (64-bit) Python NOT required — bundled inside the .exe Microsoft Excel 2016 or later — for opening the output report and using live formulas RAM 4 GB minimum; 8 GB recommended for large files Disk Space 500 MB for the .exe; additional space for input and output files Network Not required — application runs fully offline Antivirus May require one-time exception on first launch of the .exe 11.3 Step-by-Step User Instructions Step 1 — Launch Copy VLDS_Automation.exe to Desktop or project folder. Double-click to launch. On first launch, Windows SmartScreen may warn — click 'More info' then 'Run anyway'. Step 2 — Upload Files Click Browse next to VLDS Main File — select the quarterly sales export. Click Browse next to DF & RECD File — select the DF-RECD exclusion records. Click Browse next to Previous Year Summary — select the same quarter from last year. Click Browse next to Combined File — select the 3-sheet reference workbook. Verify the auto-detected columns shown in the green info box are correct. Step 3 — Configure Select Quarter (Q1–Q4) and Year, or type a custom year. Select Payout Type: Quarterly or Annual. Step 4 — Run Click the Run button. Processing runs in background. Progress bar advances through 9 steps. A yellow banner advises not to close the window. Wait for completion. Step 5 — Save and Verify Click Save Report — choose location — saves .xlsx output. Click Save Log — saves .txt audit log. Open the log file and review the EXCLUSION AUDIT REPORT section to verify all exclusion items matched correctly and the revenue impact is as expected. Open the Excel report. On Sheet 2 (Final Summary), verify the Grand Total revenue matches stakeholder expectations. Step 6 — Post-Generation Editing To correct any value in the Final Summary: click the cell, type the new value, press Enter. All formula columns in that row recalculate automatically. No re-run of the application is needed for such corrections. 11.4 Quarterly Checklist # Task When Who 1 Update Exclusion List (Sheet 2 of Combined File) with current quarter criteria Start of quarter Finance Analyst 2 Update Slab Table (Sheet 3) if incentive rates have changed Start of quarter Finance Manager 3 Export VLDS Main File from sales system After quarter close Finance Analyst 4 Obtain DF & RECD File for the quarter After quarter close Finance Analyst 5 Retrieve Previous Year Summary from archive Before running Finance Analyst 6 Run VLDS Automation — upload files, configure, click Run After all files ready Finance Analyst 7 Download and review the audit log — check exclusion report, revenue impact After run Finance Analyst 8 Verify Grand Total in Final Summary matches stakeholder expectation After run Finance Analyst 9 If revenue is higher than expected: check UNMATCHED items in log — these exclusions did not filter any rows If mismatch found Finance Analyst 10 Save Report and Log to quarterly archive folder After verification Finance Analyst 11.5 Troubleshooting Issue Likely Cause Solution Revenue higher than expected in Final Summary Some exclusion items did not match any rows Download log → check UNMATCHED ITEMS section → verify spelling in exclusion file matches VLDS data exactly Same dealer appears as two rows in pivot Customer name differs between files (e.g., with 'formerly known as') Deduplication should handle this;
